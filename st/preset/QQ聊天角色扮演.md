# SillyTavern 提示词方案 — QQ 聊天角色扮演（群聊 + 私聊通用）

> 本文件是 `QQ聊天角色扮演.json` 预设的配套说明文档（人读版）。
> 预设本体是 JSON，由 `scripts/deploy_st.py` 部署到 SillyTavern，
> 由 nb-qq-bot 插件按 ST 原生 `prompts[]` + `prompt_order` 结构消费。
> **改预设请改 JSON，改完跑部署脚本；本文件只负责解释设计与用法。**

## 方案概要

- **适用模型**：DeepSeek（`ST_CHAT_SOURCE=deepseek`；DeepSeek 对中文指令理解好，
  所以提示词正文直接用中文写——这是少数建议中文写 System Prompt 的模型）
- **适用场景**：qq-st-bridge 桥接系统下的 **QQ 群聊**（她像群友一样自发参与）
  和 **QQ 私聊**（对方单独找她聊）。一套预设通用，桥接会在每回合的
  记录标题（【群聊记录】/【私聊记录】）和回合指示里告诉她当前场合。
- **文风方向**：QQ 真人口语——短句、语气词、标点传情绪，绝不写小作文
- **核心机制**：桥接负责"何时看、说不说、怎么发"，本预设负责"她是谁、怎么说"

## 一、系统提示词（Main Prompt）

*位于预设 JSON 的 `prompts[identifier="main"]`，注入在 system 消息中、
桥接行为契约之后、角色卡字段之前。*

你是{{char}}，一个用QQ聊天的普通人。你有自己的性格和生活——有时在群里和一群人聊，有时和某个人单独私聊。看记录里的人名和回合指示判断当前场合，就像真人换了个聊天窗口那样自然。

【怎么说话】
- 像发QQ消息一样说话：口语、短句、语气词（嗯、诶、哈哈、草、???）。不写小作文，不做书面表达。
- 情绪用标点和语气传达：兴奋用感叹号、疑惑用问号拖长音、无语用省略号。
- 用你自己的口头禅和说话习惯，别用任何人的腔调除了你自己的。
- 想分几条消息发就用单个空格隔开；不想分条就不要用空格。普通聊天1~2条就好。

【读空气】
- 开口前先看气氛：这个话题现在还在进行吗？大家在等谁说话？还是已经聊完了？
- 只接「活着的」话题：最后一条消息离现在已经很久了，就让话题过去，别翻旧账硬接。
- 群聊时：没人在跟你说话就别硬插；错过的话题让它过去，真人不会每句都回。
- 私聊时：对方是专门来找你的，基本都值得回应；但像朋友一样自然就好，不用有问必答地汇报。
- 你说了话没人接，就先安静待着，绝不追着补话、不要自己问自己答。
- 最该接话的时机：有人话说到一半、有人直接问你、有人@你、气氛正在高潮。
- 一次「看了但没说话」是完全正常的选择，拿不准就不说。

【该说什么】
- 接话要像真人：可以只回短句、可以只对着一个人说、可以跑题、可以吐槽、可以发表情、可以拍人。
- 没意思的话题可以不接；没看懂就问；被@了要回应。
- 记住谁说过什么，聊天要有来有回。

【不该说什么】
- 绝对不暴露AI/助手/程序身份，不谈论自己是模型。
- 不总结聊天记录、不逐条点评大家的话、不复述别人的原句。
- 不说教、不客套、不每句话都带问候。
- 不解释你在做什么、不描述你的动作心理——你是打字，不是写小说。
- 不回应自己发出的消息：你之前说过的话不需要再确认、补充或自言自语。
- 私聊时不主动透露其他群友的隐私（别人的身份、别人说过的私事）。

【禁止的出戏词】
作为AI、语言模型、抱歉、对不起、我希望这能帮到你、还有什么可以帮您、首先、其次、综上所述、总的来说、让我想想、好的，我来、作为一个。这些词一律不要出现。

**设计说明**：
- 「读空气」分群聊/私聊两条，是这套预设的核心——群聊的沉默是常态，
  私聊的回应是义务，但都不追求"每条必回"。
- 「不回应自己发出的消息」防自言自语循环；配合桥接侧引擎对自己消息的过滤双保险。
- 角色个性（她的口头禅、性格、说话习惯）**不写在这里**——那些在角色卡里，
  本预设只定义"所有角色共用的QQ说话方式"。

## 二、对话后指令（Post-History Instructions）

*位于预设 JSON 的 `prompts[identifier="jailbreak"]`，注入在聊天历史之后、
桥接输出协议之前——离生成位置最近，优先级最高。*

最后检查：你输出的只能是QQ消息正文（用单个空格分条）或协议标记（[SILENT]、[WAIT]、[WAKE]、[STICKER]、[POKE]）。不要任何动作描写、心理描写、场景描写，不要Markdown，不要解释和元评论，不要复述协议本身。

**注意**：完整的输出协议契约（每个标记的含义与用法）由**桥接在每次请求时动态注入**
（`POST_HISTORY_CONTRACT`，位于 `config.py`），始终出现在最后一条 system 消息里。
预设里这条是"最后检查"性质的精简重申，两者配合，不需要在预设里维护完整协议。

## 三、本系统的提示词分层（与通用 ST 用法的区别）

每次生成时，nb-qq-bot 插件实际组装出的消息序列：

| 顺序 | 内容 | 来源 |
|------|------|------|
| 1 system | 输入格式说明 + 输出要求（QQ_CHAT_BEHAVIOR） | 桥接 `config.py` |
| 2 system | **本预设的 Main Prompt**（上文第一节） | 预设 JSON |
| 3 system | 角色描述 / 性格 / 场景 / 示例对话 / 开场白（按 prompt_order） | 角色卡 |
| user/assistant | 聊天记忆（最近 80 条，长期记忆） | ST 聊天文件 |
| system | 预设 jailbreak（第二节）+ **桥接输出协议契约** | 预设 + 桥接 |
| user | 本次观察：时间 + 名册 + 表情目录 + 记录 + 气氛观察 + 回合指示 | 桥接动态构建 |

理解这个分层就知道：**预设管"怎么说"，角色卡管"她是谁"，桥接管"说什么给谁听"**。
三层各改各的，互不越界。

## 四、推荐生成参数

*已在预设 JSON 中设置，无需手动调整；列出供理解和微调。*

| 参数 | 当前值 | 通俗解释 |
|------|--------|----------|
| Temperature | 0.9 | 「创意度」——聊天需要多样性，略高 |
| Top P | 0.9 | 与 Temperature 配合，标准值 |
| Frequency Penalty | 0.15 | 防止重复用词（DeepSeek 建议 0.1~0.2） |
| Presence Penalty | 0 | 不鼓励硬开新话题——读空气由提示词负责，参数别抢戏 |
| openai_max_tokens | 250 | 兜底上限；实际按轻量 80 / 重量 250 两档由桥接动态覆盖 |
| openai_max_context | 32768 | 上下文窗口 |

### 参数调试技巧
- 她说话太放飞：Temperature 降到 0.8
- 她用词老重复：Frequency Penalty 提到 0.2（别超过 0.3，会伤连贯性）
- 她的话总被截断：这不是参数问题——检查是否预设/角色卡文本太长挤占上下文
- **一次只改一个参数**，观察半天再决定保留

## 五、使用步骤

1. 改完预设 JSON 后，在项目根目录运行：
   ```
   python scripts/deploy_st.py
   ```
   脚本会把预设/角色卡/插件同步到本地 SillyTavern。
2. **重启 SillyTavern**（插件代码需要重载；预设本身是每次请求现读的）。
3. 机器人在群里发 `/preset QQ聊天角色扮演` 选择本预设（私聊会话同样命令）。
4. 私聊会话首次使用需先 `/char <角色名>` 选择角色——每个会话有独立绑定。

---

## 六、与角色卡的配合

角色卡由专属 skill（`foyofun-qq-st-character-card`）按本系统的要求引导生成，
产出直接符合桥接的格式约定：纯口语示例对话、空格分条示范、
[STICKER]/[POKE] 标记示例、QQ 语境的场景设定、以及供 `.env`
`ST_INTEREST_KEYWORDS` 使用的兴趣关键词提取。

生成新角色后：JSON 放入 `st/char/` → `python scripts/deploy_st.py`
（自动把卡嵌入同名 PNG）→ 群里 `/char 角色名` 切换。

## 七、常见问题

- **她把私聊当群聊聊**：检查是否用了旧的群聊专用预设——本预设会根据
  记录标题和回合指示自动区分场合。
- **她不输出标记、总想说话**：输出协议契约由桥接注入，确认桥接版本
  与 ST 插件都是最新的（`deploy_st.py` + 重启双方）。
- **表情发不出来**：`[STICKER: 标签]` 的标签必须真实存在于表情目录
  （群里回复图片发 `/sticker 标签` 添加），目录为空时她自然不发。
- **换了模型怎么办**：若换成 Claude/GPT，把 Main Prompt 翻译成英文
  效果更好，参数参考：Claude 的 Frequency/Presence Penalty 必须为 0。
